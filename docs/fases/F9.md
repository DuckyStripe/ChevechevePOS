# F9 — Reportes y tablero (brief ejecutable)

Para agentes implementadores (`sonnet`: `api-dev` para B y C; `web-dev` para D). **Manda `docs/CONTRATOS.md`** (§2.9 con
sus «Reglas comunes», §2.12 B13, §4.4 «Reportes (F9)» y la fila `GET /api/tablero`, §5 `reportes.ver`/`costos.ver`, §6
completo); este brief solo reparte, ordena y fija los números de prueba. Si algo no cuadra con el contrato: se reporta, no
se decide. Reglas de `CLAUDE.md` vigentes (sin commit/push/ramas/worktrees; `.env*` no se editan; pruebas solo contra
`chevechevepos_pruebas`).

**Regla del dueño: nada de builds** hasta terminar el plan. Validación: solo lint, typecheck y pruebas. Al cerrar F9 se
termina el plan de F1–F9: **la validación final con builds, APK y teléfonos** (PROGRESO «Pendientes») la decide el dueño.

**Requisito**: F8 en `main`. Migración **009** (F8 no tiene migración; CONTRATOS §2). Solo lectura: F9 no mueve dinero ni
stock, pero **expone costos y utilidad**: el revisor (opus) revisa permisos por campo.

## Supuestos y decisiones

| Supuesto / decisión | Efecto en F9 |
|---|---|
| [P8]–[P10] precio final, sin impuestos | Ningún reporte ni KPI tiene IVA/IEPS |
| [P37] solo el dueño ve costo y utilidad | `utilidad`, `ganancia`, `inventario-valorizado`, `utilidad_mes` y `precios_bajo_costo` exigen `costos.ver` |
| [P28] sin comisiones | El reporte de entregas por repartidor es la base si algún día se pagan |
| §6 gastos de operación fuera de alcance | Solo los gastos del turno de ruta restan, en `ganancia` por ruta (B13) |
| Días en hora de México (§0) | Toda fecha de reporte = `fn_fecha_local(creado_en)`; filtros `desde/hasta` inclusivos, máx. 366 días |
| Decisión: `margen = round(utilidad / importe, 4)`, `null` si `importe ≤ 0` | Un día con más devoluciones que ventas no divide entre cero ni da margen absurdo |
| Decisión: «público en general» y «sin ruta» son una fila con `clave null` | La pantalla las nombra con su etiqueta de control |
| Decisión: «por caducar» no tiene reporte nuevo | Sigue en `/inventario` (F2, `v_por_caducar`); el tablero da el conteo y enlaza ahí (una regla, una pantalla) |
| Decisión: `agrupar=metodo` usa los pagos de ventas `completada` (bruto) | Las devoluciones no se reparten por método; el efectivo devuelto está en `cortes` |
| Decisión: CSV en el navegador desde el JSON ya recibido, UTF-8 con BOM, montos como vienen (string) | Sin ruta de exportación en la API |

## Paquete C — API (dueño: `apps/api/src/modulos/{reportes,tablero}/**`, `apps/api/test/{reportes,tablero}.test.ts`, `apps/api/test/ayuda-f9.ts`; 2 líneas en `src/modulos/index.ts`)

| Módulo | Contenido |
|---|---|
| `reportes` | Las 10 rutas de §4.4 «Reportes (F9)». `agrupar` con zod `enum` (lista blanca) → columna por un mapa fijo en el módulo; **nunca** se interpola texto del cliente. `desde ≤ hasta` y ≤ 366 días (`400 VALIDACION`); def. el mes en curso. Toda suma, margen y cubeta en SQL (`GROUP BY` sobre las vistas); la API no suma. Etiquetas (`etiqueta`) = nombre de la entidad o la fecha `YYYY-MM-DD`. Permiso por ruta como §4.4 (`utilidad`, `ganancia`: `reportes.ver` + `costos.ver` con `exigirPermiso`; `inventario-valorizado`: `costos.ver`; `cuentas-por-cobrar`: `cobranza.ver`; `bajo-minimo`: `inventario.ver`; `cortes`: `caja.supervisar` o `rutas.liquidar`). |
| `tablero` | `GET /tablero` (`'sesion'`): cada campo solo si el usuario tiene el permiso de su reporte: `ventas_hoy` (`reportes.ver`; importe neto de hoy de `v_ventas_lineas`), `utilidad_mes` (`reportes.ver` + `costos.ver`; mes local en curso), `cxc_total`, `cxc_vencido` (`cobranza.ver`; de `v_saldo_cliente`), `bajo_minimo` (`inventario.ver`; filas de `v_bajo_minimo`), `por_caducar` (`inventario.ver`; filas de `v_por_caducar` con `dias_restantes ≤ dias_aviso_caducidad`), `precios_bajo_costo` (`costos.ver`; filas de `v_precio_bajo_costo`). Sin permiso, la llave **no existe** (no `null`). |

Pruebas de API obligatorias (código exacto): cada reporte con el juego de B da los mismos números por HTTP; Administrador
`GET /reportes/utilidad` → 403 `SIN_PERMISO {permiso:'costos.ver'}` (igual `ganancia` e `inventario-valorizado`); Cajero
`GET /reportes/ventas` → 403 `SIN_PERMISO {permiso:'reportes.ver'}`; `agrupar=nombre;drop` → 400 `VALIDACION`; `desde >
hasta` → 400; 367 días → 400; ninguna respuesta tiene llaves `iva`/`ieps`/`impuesto` (recorrido recursivo); tablero:
Dueño ve las 7 llaves, Administrador ninguna de costo, Repartidor `{}`; `tablero.ventas_hoy` = total de
`/reportes/ventas?desde=hoy&hasta=hoy`, `cxc_total` = total de `/reportes/cuentas-por-cobrar`.

Validación C (en su turno): lint + typecheck de `apps/api` + `npm run prueba --prefix apps/api -- test/reportes test/tablero`.
