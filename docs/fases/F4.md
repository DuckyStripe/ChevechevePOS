## Paquete B — migración 005 y pruebas SQL (dueño: `apps/api/db/migraciones/005_push.sql`, `apps/api/test/sql/005_push.test.ts`)

`005_push.sql` (DDL exacto de §2.5):

1. Tablas `dispositivo` (+ `idx_dispositivo_usuario`) y `notificacion_envio` (+ `idx_envio_pendiente`, `uq_envio`).
2. `fn_registrar_dispositivo(p_usuario_id, p_jti uuid, p_token text, p_plataforma text, p_version text) returns bigint`:
   sesión `p_jti` viva, del usuario y con `origen = 'app'` (si no `SOLO_APP`); upsert por `token_push`: si estaba en
   otra sesión/usuario se reasigna (un teléfono, un dueño) y se limpia `revocado_en`; actualiza `ultimo_uso_en` y
   `app_version`. `fn_quitar_dispositivos(p_usuario_id, p_jti uuid, p_token text default null) returns integer`
   (quita el de ese token o todos los de esa sesión; descarta sus envíos pendientes).
3. `trg_notificacion_encolar` AFTER INSERT ON `notificacion`: un `notificacion_envio` por dispositivo activo del
   usuario (`revocado_en is null` y sesión sin `cerrada_en` y no expirada) salvo `notificacion_preferencia.push =
   false` para ese evento; `ON CONFLICT DO NOTHING`.
4. `trg_sesion_cerrada_revoca` AFTER UPDATE OF `cerrada_en` ON `sesion`: revoca sus dispositivos y pasa a
   `descartada` sus envíos pendientes.
5. Funciones del despachador (las llama `envio.ts`; el SQL decide los estados): `fn_envios_tomar(p_limite integer)
   returns table(envio_id, token_push, titulo, cuerpo, datos, evento, notificacion_id)` (`FOR UPDATE SKIP LOCKED`,
   pendientes con `siguiente_intento_en <= now()`; los de > 24 h pasan a `descartada` y no se devuelven);
   `fn_envio_resultado(p_envio_id, p_resultado text, p_error text)` con `p_resultado ∈ ('enviada','temporal','invalido')`:
   `enviada` → `enviada_en`; `temporal` → `intentos + 1`, espera 1, 5, 30, 120 min, al 5.º `fallida`; `invalido` →
   dispositivo revocado y `descartada`. `ultimo_error` = código de FCM, nunca el token.
6. `UPDATE app.plantilla set texto = '<texto con 15 minutos>' where clave = 'push_pin_ataque' and texto = '<texto
   sembrado en 004>'` (con `trg_auditar` de `plantilla` desactivado alrededor, como 004).
7. Sin permisos nuevos (las rutas son `'sesion'` + sesión `app`).

Pruebas SQL (`test/sql/005_push.test.ts`, `BEGIN … ROLLBACK`, código exacto):

| Invariante | Caso → esperado |
|---|---|
| Migraciones en base vacía | `app.migraciones` tiene 000–005; re-correr no aplica nada |
| Registrar | sesión `web` → `SOLO_APP`; sesión `app` → id; mismo token desde otra sesión/usuario → misma fila reasignada (un renglón) |
| Encolar | `fn_notificar('pedido_nuevo', …)` con 2 usuarios con `pedidos.gestionar`, uno con 2 dispositivos y otro con `push = false` → 2 envíos (solo del primero); dispositivo revocado o sesión cerrada → 0 |
| Sesión cerrada | `UPDATE sesion set cerrada_en` → dispositivos `revocado_en` y envíos pendientes `descartada` |
| Tomar y resultado | `fn_envios_tomar(50)` en dos conexiones a la vez → ningún envío repetido; `temporal` ×5 → `fallida` con esperas 1/5/30/120 min; `invalido` → dispositivo revocado; envío de hace 25 h → `descartada` y no sale |
| Plantilla | texto sembrado → corregido a 15 min; texto editado por el dueño → intacto |
| Token nunca en bitácora | `auditoria` no tiene `token_push` (la tabla no es auditada) |

Validación B: `npm run lint --prefix apps/api && npm run typecheck --prefix apps/api && npm run prueba --prefix apps/api -- test/sql/005`.
